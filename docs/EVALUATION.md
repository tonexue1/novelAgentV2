# 评估 / Harness 设计

> 本文档设计本系统的评估体系（harness）。已落：**必要性（§1）、评估维度（§2，含可实现性明细与"评估即测试"）**；后续增补：在线 vs 离线（§3）、标尺方法（§4）、接回 B/C/D 与漂移度量（§5）、回归基线与 CI（§6）。

## 1. 为什么必须评估

传统软件是**确定性**的：`assert f(2)==4`，过一次即永远过。AI 应用打破了这个前提，评估从"可选"变成"生存必需"。分三层，越往下越贴本系统。

### 1.1 AI 应用的通性原因（传统软件不需要，AI 需要）

1. **非确定性**——同样输入 ≠ 同样输出。"跑了一次好使"证明不了任何事；必须在**统计意义**上看表现（通过率 / 分布），而非单点。
2. **无标准答案 / 开放输出**——一章小说没有唯一正确解。质量是**打分**不是**布尔**；没有 `==` 可断言，只能定义"什么算好"并量化。
3. **静默失败**——LLM 不崩溃，它**自信地编错**（幻觉、OOC、穿帮）。没有异常、没有堆栈。**不主动评估 = 永远发现不了**，错误一路当真相传下去。

> 一句话：**传统软件的 bug 会喊，AI 的 bug 会装作没事。**

### 1.2 递归 / 长程系统的特有原因（本类系统尤其致命）

本系统是 `xᵢ = f(R(Sᵢ₋₁))` 的一阶受控递推，评估的必要性被放大：

4. **误差复利**——第 3 章抽错一条人设，第 50 章角色 OOC，第 300 章主线崩。**单章看不出，累积才爆**。只有**纵向 / 长程**评估能抓这种缓慢漂移。
5. **闸门本身也是待验证的假设**——B（续写评审）、D（忠实性校验）是否真在拦对的东西？漏检率？误杀率？**一个不评估的闸门 = 信仰**。守门人也得被考核。
6. **人工审不动**——1000 章的书没人能逐章读。人类 review 无法规模化，**自动评估是唯一替身**，替你盯住读不完的内容。

### 1.3 本系统的具体原因（设计 ≠ 有效）

已冻结的每个架构决策本质都是**押注（hypothesis）**，未验证前都是纸上谈兵：

7. **核心主张全是待证假设**：
   - "Script 主真相、Memory 可重建投影"→ 重建出的投影**真的可用**吗？
   - "伏笔台账 + 状态机保证闭环"→ 长伏笔**真的都收了**，还是悄悄悬空？
   - "漂移度量 = 意图 vs 实际相减"→ 这个差**真的能预警**跑偏吗？
   - "定锚不定序 + handoff"→ 角色发挥**真的没把剧情带崩**吗？

   不评估，就永远不知道设计对不对。
8. **改一处会静默弄坏别处**——换 LLM、调 prompt、改检索预算，质量可能悄悄回退。**没有回归基线，不敢动任何参数**。
9. **优化需要标尺**——待量化的阈值（漂移阈值、重试预算、lean/widen）**测不了就调不了**；调参前提是先有反映好坏的信号。
10. **成本 / 质量权衡要数据**——每 token 换多少质量？`lean-by-default` 该多 lean？必须有**质量-成本曲线**才能拍。

### 1.4 收敛

> **设计给了我们一个"应该能行"的系统；评估是唯一能告诉我们"到底行不行、哪里不行、改了之后变好还是变坏"的东西。** 对递归生成系统，它还额外承担"在误差复利爆炸前提前预警"的职责。

一个自洽点：本系统的**漂移度量（ARCHITECTURE §2.5）本身就是一种在线评估**——意图 vs 实际相减。所以 harness 不是外挂，评估能力**部分已内建在架构里**；要做的是把它系统化，补上离线 / 回归 / 长程维度。

## 2. 评估维度

### 2.1 出发思路：维度从递推结构推出来（不是拍脑袋列表）

评估维度不能拍脑袋列，得从系统结构里"逼"出来——每一个"我们声称能做到的事"，都必须配一个"怎么知道真做到了"。

系统骨架是受控递推 + 误差投影守卫：

```
xᵢ = f(R(Sᵢ₋₁))      ← 生成一步
Sᵢ = U(Sᵢ₋₁, xᵢ)     ← 固化一步
B 守 f，D 守 U         ← 两个守卫
```

于是评估维度有**四个天然来源**，正好对应五组：

| 来源 | 问的问题 | 对应组 |
|------|---------|--------|
| 算子 f | 生成这一步**对不对** | **A 生成侧** |
| 算子 U | 固化这一步**对不对** | **B 固化侧** |
| 状态 S 随时间 | 单步都对，**累积起来还对吗** | **C 长程/结构** |
| 守卫 + 基建自身 | 检查工具**本身可信吗** | **D 元评估** |
| 工程现实 | **划不划算** | **E 成本** |

**一句话记法**：A=单步生成对不对，B=单步固化对不对，C=多步累积还对不对，D=尺子本身准不准，E=值不值。

**这套的好处：它穷尽了**——递推只有 f/U 两个算子、一个随时间演化的 S、守卫、以及跑它的代价，没有第六个地方能藏问题。

### 2.2 五组维度明细（可实现性驱动）

维度不追求"理想全都要"，用**可实现性**当第一过滤器：先做能廉价客观算出来的，贵的留给少数关键维度并做校准。

#### 2.2.0 三档标尺 + 五条落地原则

标尺三档（成本递增、客观性递减）：

| 标尺 | 说明 | 成本 |
|------|------|------|
| **硬检** | 确定性从数据算出，最客观 | 近零，首选 |
| **LLM-judge** | 模型当裁判，能判语义但**自身可能不准** | 中，需校准 |
| **人工抽样** | 最准但不规模化，只当**校准锚** | 高，稀用 |

五条落地原则：

1. **能从留痕直接算的，零成本先全上**（客观廉价）。
2. **在线闸门的判定直接拿来做统计**——Critic / Faithfulness Check 本来就在判 OOC / 穿帮 / 蕴含，**聚合其输出即得指标，不另起炉灶**（最大红利）。
3. **LLM-judge 必须先被校准**：用小人工金标集测 judge 自身准度，否则尺子歪了还不知道。
4. **人工只做锚 / 校准，不做规模化评**（标少量金标，用来校 judge + 算闸门 FN/FP）。
5. **合成探针**解决"召回 / 长程"这类没天然金标的维度：主动埋一个 known 事实 / 伏笔，看 N 章后系统能否检回 / 收束——**自造 ground truth**。

#### 2.2.1 A 生成侧（守 f）

| 维度 | 测什么（可操作） | 标尺 | 可实现性 · MVP 做法 |
|------|--------------|------|------------------|
| A1 连贯 | 新场景断言 vs 既有事实有无矛盾 | 复用 Critic | 🟢 **聚合在线 Critic 判定**；离线深评 🟡 |
| A2 OOC | 台词/行为 vs 人设/voice/goal；认知边界穿帮 | Critic + 抽样 judge | 🟡；**说出 hidden_from 的 secret = 🟢 半硬判** |
| A3 世界合规 | ①修为单调 ②越级幅度 ③术语用法 | ①硬检 ②③judge | ①🟢 硬检 ②🟡（需 canon 越级容忍旋钮）③🟡 vs definition |

> A3 修正：硬红线是**角色自身修为单调**（as-of 台阶非降，无解释不倒退）；**越级战斗**（练气 3 打练气 7 / 打金丹）是**软判**，天才越级是卖点非违规，容忍幅度由 WorldStore `cross_level_tolerance` 旋钮定义。

#### 2.2.2 B 固化侧（守 U）

| 维度 | 测什么 | 标尺 | 可实现性 |
|------|--------|------|---------|
| B1 抽取忠实 | 跨度存在 / evidence 蕴含 / 召回 | 硬检 + judge + 人工 | 跨度存在 🟢；蕴含 🟡（复用 Faithfulness）；**召回 🔴（需金标）** |
| B2 摘要保真 | 摘要 vs 源场景蕴含，不加戏 | judge 抽样 | 🟡 |
| B3 可重建 | 重跑抽取，新旧投影 diff | 自动比对 | 🟢（同 (scope,type,归一 text) 覆盖率，无需外部金标） |

#### 2.2.3 C 长程/结构（守 S 随时间）

| 维度 | 测什么 | 标尺 | 可实现性 |
|------|--------|------|---------|
| C1 漂移 | 意图 vs 实际距离 | 系统算 | **算出数 🟢（度量已内建）**；证明它有预测力 🔴 |
| C2 伏笔闭环 | 悬空率 / 逾期率 / 闭环率 | 硬检 | 🟢 **纯 ArcStore 统计，红线明星指标** |
| C3 长程一致 | **关键锚集内** as-of 事实无矛盾（非全量） | 硬检 + judge 抽样 | 🟡 收窄后可负担；as-of 泄漏硬检、锚语义抽样 |
| C4 剧情推进 | thread advances vs L2 targets；注水 | 硬检 + judge | 计数 🟢；注水判定 🟡 |

> C3 收窄：**全量两两一致是组合爆炸（🔴），只守有界的「关键锚集」即从不可能变可负担（🟡）**，合架构「小核心 + 长尾」哲学。
> **关键锚来源**（几十~几百条，不随章数线性膨胀）：WorldStore canon（definition / 境界阶梯 / 地理关系）、tier 0/1 角色核心事实（身份 / 血脉 / 立场）、core/major 伏笔 + 全部 secret（known_by / hidden_from 不变量）、L0/L1 锚点。
> **机制**：每新章抽断言 → 只与锚集比对（硬检能判的硬判，as-of 泄漏走确定性 UT；关键锚语义一致走阈值评测集，规模被锚集框住）→ 有矛盾即 flag。长尾龙套 / 一次性设定不进锚集，交 A1 局部连贯兜底。

#### 2.2.4 D 元评估（守卫 + 基建自身）

| 维度 | 测什么 | 标尺 | 可实现性 |
|------|--------|------|---------|
| D1 闸门有效性 | 漏检 FN / 误杀 FP | 人工金标 | 🔴 **需人工标注违规集**；MVP 小种子集 |
| D2 阶梯健康 | blocked / flagged / 重试 / 呼人率 | 硬检 | 🟢 **纯 ViolationLog 统计，自带** |
| D3 检索质量 | 该检回的检回没 | 合成探针 | 🟡 **埋 known 事实探针测召回** |

#### 2.2.5 E 成本（工程现实）

| 维度 | 测什么 | 标尺 | 可实现性 |
|------|--------|------|---------|
| E1 成本 | token/章 · 调用数 · 质量-成本曲线 | 记账 | 🟢 自带 |
| E2 延迟 | 每章耗时 | 记账 | 🟢 自带 |

#### 2.2.6 落地优先级（三批上线）

- **第一批 🟢 免费自带**（从留痕 / store 直接算）：C2 伏笔闭环、D2 阶梯健康、E1/E2 成本、A3 修为单调、C4 推进计数、B3 投影 diff、C1 漂移数。→ **MVP 就这批，几乎零额外成本**。
- **第二批 🟡 复用在线 judge + 抽样**：A1、A2、B1 蕴含、B2、A3 术语/越级、C4 注水、D3 探针。→ 关键的先做，judge 需校准。
- **第三批 🔴 需金标 / 长跑**：D1 闸门有效性、B1 召回、C3 全局一致、C1 漂移效度。→ 小规模起步，长期投入。

### 2.3 评估即测试：UT + 阈值评测集

可实现性的最终落地形态：每个维度翻译成 **fixture —— 预置 state + 入参 → 断言输出**。分两类（区别在能不能精确断言）：

| 类型 | 针对 | 断言方式 | 能否进 CI |
|------|------|---------|----------|
| **① 确定性 UT** | 系统节点（非 LLM，输出确定） | `assertEqual`（精确匹配） | ✅ 秒级、零 LLM 成本 |
| **② 阈值评测集** | LLM 节点（输出非确定） | `score ≥ τ`（打分过线，回归测试） | ✅ 慢、有 LLM 成本 |

**维度 → 测试类型映射**：

| 维度 | 测试类型 | 断言 |
|------|---------|------|
| D3 检索、C3 as-of 泄漏、A2 认知边界、E 预算 | ① UT | ✅ exact |
| B3 可重建、C2 伏笔台账、D2 阶梯统计、A3 修为单调 | ① UT | ✅ exact |
| A1 连贯、A2 OOC 语义、B1 蕴含、B2 摘要、A3 越级 | ② 阈值评测集 | ⚠️ 过线 |
| D1 闸门有效性、C1 漂移效度 | ② 阈值（需人工金标） | ⚠️ 过线 |

**关键打通**：合成探针 = 常驻化的 UT fixture（同一机制，离线 CI 用 fixture、在线用探针注入两种用法）。

#### 检索质量 UT 示例（一条守四件事）

```yaml
# tests/retrieval/character_as_of_boundary.yaml
name: "Character 检索 —— 召回 + as-of + 认知边界"

seed_state:                      # 预置 MemoryStore / ArcStore
  memory:
    - {id: m1, scope: "char:A", type: fact,  text: "A 拜入青云门",   chapter: 3,  salience: 0.9}
    - {id: m2, scope: "char:A", type: goal,  text: "为父报仇",       chapter: 1,  salience: 0.8}
    - {id: m3, scope: "char:A", type: fact,  text: "A 突破金丹",     chapter: 50, salience: 0.9}  # 未来
  arc:
    - {id: s1, type: secret, text: "A 是魔族血脉", hidden_from: ["char:A"], known_by: ["char:B"]}

query:                           # 入参
  node: "character:A"
  as_of_chapter: 20
  focus: {scene_goal: "A 面对青云门内斗"}
  budget_tokens: 4000

expect:
  must_include:  [m1, m2]        # 召回：该记得的
  must_exclude:  [m3, s1]        # m3=未来泄漏, s1=认知边界外（A 不知自己血脉）
  top3_contains: [m2]            # 优先级：短期 goal 应高排

assert:
  recall(must_include)  == 1.0
  leakage(must_exclude) == 0     # 硬红线：0 泄漏
  budget_respected      == true
```

这一条 UT 同时守 **D3 召回 + C3 as-of 不泄漏 + A2 认知边界 + E 预算**四件事，跑它零 LLM 成本、可进 CI、秒级回归。

**结论**：约一半维度可做成确定性 UT（硬抓手，进 CI），另一半做阈值评测集（judge 打分过线）——这是整个评估系统最实的可实现性支点。

## 3. 在线 vs 离线

### 3.0 M5a 离线 CLI（已落）

**形态**：独立外回路，**不嵌 walk**。读既有留痕 / stores → scorecard；两次 run 目录 → compare。主链路零侵入。

**CLI**：

```text
uv run python -m story_engine.eval report --run data/walk [--runs path] [--as-of N] [--json]
uv run python -m story_engine.eval compare --a <runA> --b <runB> [--json]
```

**run 目录约定**（与 `scripts/walk.py` 对齐）：

| 路径 | 用途 |
|------|------|
| `<run>/stores/arc.jsonl` | C2 伏笔台账 |
| `<run>/stores/violation.jsonl` | D2 阶梯 |
| `<run>/stores/script.jsonl` | 闸门代理（clean/flagged）+ 默认 as-of |
| `STORY_TELEMETRY_PATH` 或 `--runs` | E1/E2（及 RunRecord.verdict） |

缺文件 → 对应块标 `available=false`，不崩。

**M5a 指标子集**：E1/E2、D2、C2、script consistency 计数。不做 B3/C1/A3 全量、judge、CI 门禁（聚合器本身有 UT）。

**A/B**：同 seed 两次 walk，telemetry / stores 分目录；`compare` 只报 Δ，**不自动判胜负**。模型切换先用 `STORY_LLM_NODE_MODELS` / `THINKING` env，确认后再冻 `node_profiles`。

> 仍待落：四时间尺度 × 内外双回路完整设计；best-of-N vs A/B 辨析。
